# 2026-11-22 격리 브라우저 표시 검증

11월 22일 개정의 시장·속도 한 줄과 대표 신호·배지 한 줄을 실제 빌드 화면에서 확인했다. 합성 3개 사례와 고정 일봉 2개 사례가 통과했다. 캔버스 클릭 후 오른쪽 패널의 선택 날짜, 그 날짜의 실제 HTTP API 응답, 화면 문구를 대조했다. jsdom이나 API 응답만으로 화면 검증을 대체하지 않았다.

## 실행 범위

- Playwright Chromium **headless**, 새 비영구 브라우저 컨텍스트, 한국어 로캘.
- 합성 및 일반 고정 사례는 1440×960, 고정 2023-06-11은 3200×960.
- 개인 데스크톱·GUI·기존 브라우저 프로필·사용자 DB는 접근하지 않았다.
- 검증용 Vite preview를 127.0.0.1에만 바인딩하고 `/api` 프록시를 명시했다. 18735→격리 합성 수동 지지 서버 18732, 18736→격리 합성 지지 미확인 서버 18733, 18737→격리 고정 일봉 서버 18731이다.
- 브라우저 요청은 해당 preview origin만 허용하는 route guard로 제한했다. 8000·18703이나 외부 주소로 요청하지 않았다.
- 각 컨텍스트에서 실험 토글의 초기 OFF를 확인하고 기존 토글을 클릭했다. 기존 선택 모드에서 캔버스를 클릭했다. 새 UI나 날짜 query parameter를 추가하지 않았다.

## 상태와 실행 중 보완 사항

최종 실행의 JavaScript pageerror, origin guard 차단, 예상 밖 요청 실패는 모두 0이다. [수동 합성 상태](manual-browser-status.json), [지지 미확인 상태](unknown-browser-status.json), [고정 일반 상태](fixed-browser-status.json), [고정 후보 상태](fixed-2023-06-11-browser-status.json)에 기록했다.

중간 실행에서 제품 코드가 아닌 검증 helper의 다음 문제를 확인하고 수정했다.

- Windows cp949 콘솔이 유니코드 `−` 출력에 실패했다. `PYTHONIOENCODING=utf-8`로 실행했다.
- 날짜 변경으로 이전 rapid-drop 요청이 정상 취소된 `net::ERR_ABORTED`를 실패로 분류했다. `useRapidDrop`의 AbortController 동작을 확인하고 이 요청 취소만 별도 기록하도록 했다. 최종 상태에는 요청 취소도 0개다.
- 고정 양수 속도에 요구되지 않은 `+` 접두를 helper가 기대했다. 실제 요구인 음수 유니코드 `−`와 소수 둘째 자리만 검증하도록 수정했다.
- 목표 날짜를 찾는 빠른 연속 클릭이 차트 더블클릭 처리에 묶였다. 단일 클릭 간격을 두고 실제 선택 날짜를 매번 읽었다. 목표 날짜에 도달한 뒤 직전 요약 대신 **목표 날짜 API 응답과 같은 대표 문구**를 명시적으로 기다렸다.

이 보완은 연구 폴더의 임시 helper에만 적용했으며 제품 로직·시장 기준·신호 기준·골든값을 바꾸지 않았다.
