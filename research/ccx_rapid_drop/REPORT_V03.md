기준 커밋 `aefe83ef583f1ae76129208ef3133cf089dfc610`, 작업 브랜치 `feat/rapid-drop-signals-v03`. 최신 원격 main은 시작 시 `f9ade54ee9691eff75cca7ed719cff47ce75132b`, 원격 v0.2는 기준 SHA와 일치했다. 기존 미커밋 `.vscode/settings.json`과 수동 도형 DB는 보존했다. **매매 DB의 파일 보존에는 실패했으며 아래 사고 기록을 먼저 확인해야 한다.**

## 매매 DB 보존 사고 — 미해결

기존 `backend/tests/test_trades.py`가 실제 `app.services.trades.DB_PATH`에서 테스트 레코드를 생성하고 모듈 종료 시 생성 ID만 삭제하는 구조였다. 전체 회귀 실행 전에 이 범위를 격리하지 못했다. 최종 해시 검사에서 실제 `data/trades.db` 변경을 발견했다.

- 작업 전 SHA-256: `d44bf4158f7393cbd0bc35b268dbf4539de032adb2485e9ed6187167cffbe393`
- 발견 후 SHA-256: `f046e9789707f1ed4768832098b51716ee60cbd3285072d4856c9a9e23360a06`
- 읽기 전용 조사에서 현재 논리 레코드는 0개, 무결성 검사는 정상이다. 그러나 삭제된 레코드의 비할당 페이지도 달라질 수 있어 원래 파일/사용자 데이터가 보존됐다고 단정하지 않는다.
- 원본 바이너리 백업은 확보하지 못했다. 비공개 작업 사본에서 헤더·sequence 조합을 검사했지만 원래 SHA와 일치하지 않았다. 실제 DB를 추측값으로 복원하거나 덮어쓰지 않았다. Git에 DB나 비공개 조사 사본을 넣지 않는다.
- `conftest.py`에 **모듈 종료 정리까지 포함하는 세션 범위 임시 매매 DB**와 실제 DB 시작/종료 해시 실패 검사를 추가했다. 이후 전체 367개 실행에서 실제 파일은 추가로 변하지 않았다. 기존 매매 제품 로직은 수정하지 않았다.

따라서 원래 DB와 바이트 단위 동일성 복구는 미해결이다. 원래 SHA와 일치하는 백업이 있어야 확정 복구할 수 있다. 이 사유와 화면 검증 제한을 숨기지 않고 Draft PR에 명시한다. 수동 도형 DB·골든값·모양 기준·엔진·설정·Streamlit 및 `.vscode`의 보호 해시는 같다.

## 구현

`research/ccx_rapid_drop/rapid_drop.py`는 수정·복제하지 않았다. 백엔드의 `rapid_drop_signals.engine()`이 그 단일 파일을 importlib로 읽고 같은 모듈 객체를 재사용한다. 기존 캔들 모양 함수와 설정 JSON도 그대로 사용한다. 기존 실험 수치는 검증용 초안이며 최적값·확정 규칙으로 승격하지 않았다.

날짜 선택 → `/api/rapid-drop?date=YYYY-MM-DD` → 백엔드 판정 → 기존 SignalPanel의 `급락 대응 · 실험`으로 연결했다. 실험 결과를 기존 독립 신호 배열이나 롱·숏 집계에 합산하지 않는다. 백엔드 기능은 기본 OFF, 프런트 토글도 기본 OFF다. 일봉 전용이며 주봉에서는 요청·표시하지 않는다.

- **하락 가속:** 현재 가속과 최근 가속 후 관찰 구간을 별도 반환한다. 후보가 발생해도 경고를 없애지 않는다.
- **첫 제동 후보:** 당시 알려진 수동 지지 반응 + 망치·역망치·도지에서 평가한다. 장대음봉 자체는 후보가 아니다. 실제 추적 가능한 기준만 발행하여 이후 무효·만료를 연결할 수 있게 했다.
- **재지지 후보:** 이전 봉까지 반등 확인, 반전 세 모양, 기존 허용대 안 종가, 꼬리 하회 시 종가 회복을 모두 확인한다. 같은 날 해당 기준이 이탈·만료되면 발행하지 않는다. 기준대 위·아래 종가나 모양 없는 접촉은 `retest_watch` 관찰로 남긴다. 가격 거리와 기존 반등 폭 이상 높아졌는지를 근거로 분리한다.
- **중복 방지:** 첫 후보는 기준·지지 버전별 한 번, 재지지 후보는 기준별 한 번 발행한다. 반복 접촉은 새 후보로 집계하지 않는다. 같은 날 같은 기준에서 두 후보 조건이 겹치면 재지지 경로를 우선한다.
- **유지/종료:** 이전 발행 객체를 덮어쓰지 않는다. 유지 목록은 과거 발생 객체를 그대로 참조한다. 이탈과 만료는 그날 별도 신호로 실제 발행 후보 ID만 연결한다. 새 기준 반응도 실제 이전 후보와 연결한다. 청산·손절 체결·자동 숏이 아니다.
- **트랩 후보:** 같은 지지 버전의 실제 이탈과 회복을 근거 사건 ID로 연결한다. 이탈 기록이 없는 회복과 구분하며 자동 롱을 만들지 않는다.
- **거래량:** 직전 평균 대비와 기준 장대음봉 대비를 각각 표시한다. 새로운 거래량 필수 조건, 점수·가중치를 추가하지 않았다.

첫 후보의 유효성 기준은 추적 기준 봉 종가 주변이다. 처음 지지에서 만들어진 기준과 기존 장대음봉 추적 중의 새 수동 반응을 구분하여, 수동 지지의 실제 가격 범위는 별도 근거로 표시한다. 자동 기준 가격을 사용자 수동 선으로 표시하지 않는다.

신호는 ID·유형·발생일·UTC 마감 확정 시각·기준 가격/출처·근거·주의사항·이전 후보 ID·원본 사건 ID를 가진다. API의 history는 선택한 날짜까지 생성된 기록이며 미래 날짜의 종료 상태로 과거 후보를 덮어쓰지 않는다. 미마감 봉과 선택일 이후 봉은 API 계산 입력에서 제외한다.

## 수동 지지 이력

기존 `manual_lines.db`는 읽기 전용 URI로 읽는다. 최초 관찰과 이후 생성·수정·삭제의 좌표 상태는 별도 append-only `data/rapid_drop_support_versions.jsonl`에 기록한다. 사용자 DB의 스키마나 데이터를 바꾸지 않으며 이력 파일은 Git에서 제외했다. 경로는 `CCX_RAPID_DROP_SUPPORT_HISTORY`로 바꿀 수 있다.

처음 관찰한 UTC 날짜의 마감부터 알려진 버전으로 사용한다. 과거 `created_at`을 근거로 소급하지 않는다. 같은 날 수정·삭제는 마감 당시 마지막으로 알려진 버전을 사용한다. 존의 시간 범위도 교차한다. 해시 연결·잠금·append/fsync로 검증하며 손상·잠금 실패 시 기존 파일을 덮어쓰지 않고 지지 미확인으로 처리한다. 기존 도형 저장 후 이력 기록만 실패하면 기존 저장을 재시도하게 만들지 않고 경고를 남긴다.

수평선과 존을 지원한다. 추세선 등 미지원 도형은 ID와 주의사항을 반환하며 수평 지지로 오인하지 않는다. 관찰 사이에 외부 앱이 직접 수정한 실제 편집 시각은 복원할 수 없다. 이 기록은 **API가 관찰한 버전 이력**이며 완전한 과거 편집 이력이 아니다. 기록 시작 이전은 미확인이다.

## 실제 표시 확인과 남은 제한

개발 서버는 고정 입력과 임시 manual/trades DB를 사용했다. 실제 Edge 화면에서 기존 차트·기존 롱/숏 숫자와, 그 아래 분리된 `급락 대응 · 실험` 섹션·`고정 마감 일봉 데이터`·시장 가속/관찰 구간·`지지 미확인`·새 발생/유지 구역을 확인했다. 큰 분석 화면을 추가하지 않았다.

고정 데이터의 2023-06-11 후보를 실제 HTTP API와 실제 프런트 컴포넌트까지 연결한 검사는 통과했다. 합성 HTTP 예제에서는 2022-01-06 첫 후보와 가속 경고가 함께 나오고, 1/7 유지, 1/8 재지지 후보가 이전 ID를 연결한다. 이 날짜·가격 경로·지지는 **합성 검증용**이다.

브라우저 연결 호스트가 제공되지 않아 Windows 화면 도구로 전환했다. 고정 데이터 패널은 확인했으나 합성 화면으로 전환하는 단계에서 도구가 현재 URL을 충분히 확인할 수 없다며 Computer Use를 중지했다. 이후 우회 UI 조작을 하지 않았다. 따라서 **합성 후보의 실제 브라우저 표시·캔버스 클릭 확인은 미검증**이다. API/jsdom 결과를 그 실제 화면 검증으로 대신 보고하지 않는다. 프로덕션 실시간 데이터 화면, 실제 과거 수동 지지 첫 후보·트랩, 추세선 지지 판정, 후보 성과·체결 가능성도 검증하지 않았다.

모의 계좌·잔고·분할 비중·체결·손익·자동 주문·RSI·임계값 최적화·텔레그램은 추가하지 않았다. main 병합과 운영 배포는 하지 않는다. 위 화면 미검증 사항을 PR에도 명시한다.
