# 급락 대응 연구 코드 검토 및 고정 일봉 전체 실행

검토일: 2026-11-19 (Asia/Seoul). 원본 실험의 실행과 구현 검토 결과이며, 운용 규칙 확정이나 성과 검증이 아니다.

## 판단에 영향을 주는 검토 결과

전략 의미가 달라지는 변경은 적용하지 않았다. `rapid_drop.py`, `replay.py`, 설정, 예제 지지, 기존 테스트를 포함한 동봉 파일 8개는 바이트 단위로 보존했다. 아래 항목은 현재 동작을 재현한 결과와 제안이다. 추가 테스트의 통과는 이 동작이 바람직하다는 뜻이 아니다.

1. **재시험의 종가 조건이 README 설명보다 넓다.** README 32행은 “허용 폭 이내의 마감은 재지지”라고 설명한다. 구현은 `rapid_drop.py:118`에서 기준 종가의 허용대 하단보다 낮은 종가만 탈락시키고, 126행에서 고가~저가가 허용대에 닿았는지 검사한다. 종가 상한은 없다. 합성 검사에서는 기준 97, 반등 후 재시험 봉의 종가 120도 `retest_preferred`다. 기존 모양 함수가 이 봉을 실제 `hammer`로 판정한다. 전체 실데이터의 재시험 7회 중 5회도 허용대 상단보다 높은 종가다: 2022-04-14, 2023-12-14, 2024-04-05, 2024-08-07, 2025-11-11. 이는 미래 참조 문제가 아니라 문서와 판정 범위의 차이다. 제안: 장중 접촉과 종가가 허용대 안에 있는 재지지를 같은 것으로 볼지 결정한 뒤 문서나 조건을 맞춘다. 현재 결과에서 이 5회를 임의로 제거하거나 재분류하지 않았다.
2. **도지와 장대음봉이 겹치면 장대음봉 관찰이 우선한다.** `rapid_drop.py:144`의 `if heavy_red`가 지지 도지의 `elif`보다 앞선다. 캔들 전체 범위 대비 몸통이 작은 도지도 시가 대비 하락률은 클 수 있다. 실제 기존 모양 함수를 사용하는 합성 사례에서 지지 반응, 고거래량, 도지, 장대음봉을 동시에 만족하지만 `direct_doji_candidate` 대신 `volume_red_watch_only`만 나온다. README의 두 가설 설명에는 이 우선순위가 명시되지 않았다. 제안: 이 중첩 조건에서의 분류 의도를 명시한다. 장대음봉을 매수 신호로 바꾸지는 않았다.
3. **하나의 기준 봉만 추적하므로 살아 있는 장대음봉 기준이 뒤의 첫 지지 도지를 가린다.** README 33행이 한 기준 봉 제약을 공개하고 있으며 구현도 일치한다. 다만 `rapid_drop.py:142`의 `anchor is None` 때문에 장대음봉 관찰 중 나타난 별도의 고거래량 지지 도지는 후보로 기록되지 않는다. 추가 테스트에서 지지 반응·도지·거래량 조건이 모두 참인데 사건은 빈 튜플이다. 두 경로를 독립적으로 모두 수집하는 코드로 해석하면 안 된다. 제안: 두 경로의 병렬 관찰 여부를 후속 설계에서 결정한다.
4. **같은 날 기준을 잃고 새 기준을 만들면 단일 `anchor_day`가 새 날짜로 바뀐다.** `rapid_drop.py:120`에서 이전 기준 날짜를 기록하지만 153행에서 새 기준 날짜로 덮는다. 합성 사례의 한 행은 `anchor_lost_on_close`와 `direct_doji_candidate`를 함께 포함하면서 `anchor_day`는 새 도지 날짜만 제공한다. 이전 행들을 추적하면 복원할 수 있지만, 한 사건 행만으로는 무효가 된 기준을 식별할 수 없다. 제안: 사건별 기준 날짜 또는 이전/신규 기준 필드를 별도로 제공한다. 출력 스키마는 이번 검토에서 변경하지 않았다.

문서 표현도 구분할 필요가 있다. README 첫 문장의 “운영 코드·DB를 읽고 쓰는 작업은 없다” 중 운영 코드의 읽기는 문자 그대로는 맞지 않는다. `replay.py`는 기존 `candle_patterns.compute_candle_shape`를 import하여 사용한다. 운영 코드를 변경하거나 운영 API·DB를 호출하지 않는다는 뜻으로 읽어야 한다. README의 19개 테스트·전체 리플레이 미실행 설명은 동봉 당시 기록이다. 이번 추가 검증은 이 문서와 `results/`에 별도로 기록했다.

## 합성 검사와 검증 불가·미실행 항목

합성 지지는 가격 96~98, 첫 사용일 2022-01-01인 테스트용 값이다. 합성 OHLCV와 기존 모양 함수로 2022-01-06 `direct_doji_candidate`, 2022-01-07 `bounce_observed`, 2022-01-08 `retest_preferred` 및 `first_wick_undercut_recovered`를 확인했다. 날짜가 실데이터 기간과 같아도 이 가격 경로는 합성이다. 실제 시장 지지나 사용자의 거래를 재현한 결과가 아니다.

**검증 불가:** 실제 지지에서의 첫 고거래량 도지 후보. 지지 입력이 없으므로 발생 0은 효과 부재를 뜻하지 않는다. 과거 수동 도형의 당시 좌표와 그 버전의 사용 가능 시점도 확인할 수 없다. `manual_lines_snapshot.json`의 존 3개는 특정 시점의 행이며 `created_at`만으로 좌표 수정 이력이 복원되지 않는다. 그 파일의 수평선 9001과 추세선 9002는 설명상 합성이다. 따라서 스냅샷을 과거 지지 이력으로 변환하거나, 현재 사용자 DB의 좌표를 과거에 소급 적용하지 않았다. 사용자의 스크린샷 거래와 성과 역시 검증하지 못했다.

**미실행:** 운영 앱 전체 백엔드/프런트 테스트, 차트 전수 수동 검사, 손익·수수료·슬리피지·체결 모델, 임계값 자동 최적화. 이번 작업은 연구 폴더만 추가하므로 운영 앱 테스트 성공을 주장하지 않는다. 실제 전체 데이터에서 `wick_not_recovered`는 발생하지 않았으며 추가 합성 분기 검사는 하지 않았다. main 병합, 운영 배포, 실제 주문도 실행하지 않았다.

## 추가 파일의 목적

- `test_review.py`: 기존 모양 함수와의 연동, 검토에서 발견한 현재 동작, 미래 지지·유효기간·중복 키 검사. 원래 19개 테스트를 변경하지 않았다.
- `run_audit.py`: 원본 replay를 별도 프로세스로 실행해 UTF-8 결과를 저장하고 전체 접두 구간·보존 검사를 재현한다. PowerShell의 기본 UTF-16 리다이렉션에 기대지 않는다.
- `results/`: 원본 코드의 실제 실행 로그, 모든 봉의 관찰값, 사건별 CSV, 실데이터/합성 결과 구분, 설정·입력·보존 해시.

전체 1,762행의 `results/observations.jsonl`은 로컬 산출물로 보관하고 Git에서는 제외했다. 작업 브랜치에는 코드·테스트·실행 로그·사건 목록·결과 요약과 보존 증거를 올린다. 전체 관찰값은 위의 replay 또는 감사 실행 명령으로 재생성할 수 있다.

실행을 위해 엔진이나 원본 실행기를 고칠 필요는 없었다. 수정 이유는 검토 재현성과 결과 기록을 추가하는 데 한정된다. 커밋과 푸시는 이 연구 폴더만 대상으로 하며, 실제 완료한 브랜치·SHA·푸시 여부는 최종 작업 응답에서 보고한다.
