# 돌파·재시험 차트 검증

빌드한 앱과 FastAPI를 같은 루프백 주소에서 열었다. Chromium에서 실제 일봉 캔버스를 클릭하고, 오른쪽 패널의 선택일과 그 클릭으로 발생한 HTTP 응답을 맞췄다. 돌파 실험의 기본 토글은 OFF이며 켜기 전 이 API의 요청은 0건이었다. 이후 상승 실험도 함께 켜서 두 패널을 비교했다.

| 입력 | 선택일 | 오른쪽 패널에서 확인한 내용 |
| --- | --- | --- |
| 고정 BTCUSDT | 2024-03-16 | 당시 도형 이력 미확인. 해당 날짜의 시장 방향만 확인 가능 |
| 합성 `zone_hold` | 01-02~05 | 종가 돌파, 다음 날 청록색 신규 롱, 유지, 하단 이탈에 따른 무효 |
| 합성 `zone_failure` | 01-03~06 | 존 내부 주의와 하단 이탈 실패 관찰은 파란색. 01-05 아래쪽 재시험 후 밀린 날에만 빨간색 신규 숏, 01-06 유지 |
| 합성 `support_recover`, `wick` | 01-02~04 중 각 사례의 사건일 | 꼬리만 넘은 날, 종가 회복 관찰일, 별도 봉에서 발행한 롱의 구별 |
| 합성 `slope_down`, `slope_up`, `slope_short` | 01-03~05 중 각 사례의 사건일 | 하향 추세선 돌파일 102와 다음 날 재시험 가격 100. 우상향 추세선 이탈의 롱 종료, 이후 회복 경로와 아래쪽 재시험 숏 경로 |
| 합성 `version_lifecycle`, `expiry` | 01-03, 01-06, 01-11 | 버전 교체·종료와 기한 만료가 종료 강조로 표시됨 |
| 합성 `gentle`, `bear_rebound` | 03-04, 03-22 | 같은 청록색 롱 후보에 정배열 근거 또는 역배열 속 반등 근거가 붙음 |

합성 날짜의 연도는 2022년이다. 합성 화면에는 **합성 데이터 · 검증용**이 표시된다. 신규 롱의 실제 색은 `#70d9b5`, 신규 숏은 `#ff929b`, 경계 주의·실패 관찰은 `#94c6ff`, 유지·종료는 `#8a8f9c`였다. 신규·유지·종료 배지와 각 단계의 날짜는 색과 별도로 읽을 수 있다. 같은 ID를 공유하는 숏은 두 실험을 함께 켰을 때 돌파 패널에 한 번 강조되고, 상승 패널에서는 그 위치를 안내한다.

- [합성 하향 추세선의 날짜별 가격과 신규 롱](results/slope_down-2022-01-04.png)
- [합성 존 재시험의 신규 숏과 기존 패널 연결](results/zone_failure-2022-01-05.png)
- [역배열 속 반등의 합성 롱](results/bear_rebound-2022-03-22.png)

12개 입력의 총 25회 클릭 결과는 [입력별 결과](results)에 기록했다. 날짜마다 HTTP 200, 선택일 문구, 후보의 원래 확인 날짜, 단계 순서, 신규·유지·종료 색을 검사했다. 마감된 가격·수동 버전 이력은 각 검증 서버가 제공하고 매매·도형 DB 및 이력은 입력마다 별도 임시 디렉터리에 둔다.

## 재현

프로젝트 루트에서 아래 명령을 실행한다. 백엔드는 프로젝트 가상환경을, 브라우저 드라이버는 Playwright·Chromium이 설치된 Python을 사용한다. 다른 브라우저용 Python을 사용하려면 `--browser-python`으로 경로를 지정한다.

```powershell
npm.cmd --prefix frontend run build
& .\backend\.venv\Scripts\python.exe -B research/breakout_retest/browser/check.py --output (Join-Path $env:TEMP 'ccx-breakout-browser')
```

한 입력만 확인하려면 `--case slope_down` 등을 붙인다. 캡처와 JSON은 지정한 디렉터리에 저장한다. 검증용 서버는 외부 요청을 차단하고 케이스가 끝나면 종료한다.
