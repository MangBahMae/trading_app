## 차트에서 선택할 날짜

고정 BTC는 2022-01-01부터 2026-10-28까지 실제 마감 일봉을 사용한다. 아래에서 입력 이름이 `fixed`가 아닌 행은 모두 **합성 데이터 · 검증용**이다. 같은 날짜라도 입력별 가격과 도형이 다르다.

| 검증 서버 입력 | UTC 선택일 | 오른쪽 패널에서 확인할 점 |
| --- | --- | --- |
| `zone_hold` | 2022-01-02~05 | 존 [100, 102] 위에서 104 마감. 다음 날 저가 101.8, 종가 103에서 청록색 신규 롱. 4일은 같은 후보 유지, 5일 종가 99에서 무효. |
| `zone_failure` | 2022-01-03~05 | 종가 101은 존 내부 주의, 99는 상향 돌파 실패 관찰과 기존 롱 종료. 5일 고가 101로 하단을 다시 시험하고 98.5로 마감하면서 빨간색 숏 후보가 한 번 나온다. |
| `support_recover` | 2022-01-03~04 | 지지 하향 이탈 뒤 상단과 같은 102에 마감하면 회복 관찰. 다음 날 저가 101.5, 종가 103에서 롱 후보. |
| `slope_down` | 2022-01-03~04 | 하향선의 3일 가격은 102, 4일 가격은 100이다. 4일 저가 99.9, 종가 103의 지지 재시험은 그날의 선 가격으로 확인된다. |
| `gentle`, `bear_rebound` | 2022-03-04, 2022-03-22 | 급등 없는 정배열의 롱 후보와 역배열 속 반등의 롱 후보. 시장 방향과 해당 도형에서 확인한 반응을 함께 읽는다. |
| `fixed` | 2024-03-16 | 기존 시장 판단은 ‘롱 우세 · 정배열 유지’. 이 날짜의 도형은 ‘당시 도형 이력 미확인’. |

실제 캔버스에서 선택한 날짜별 HTTP 응답·발행일·계산된 색상과 화면 캡처를 보관했다. [브라우저 검증과 캡처](browser/README.md)

## 판정과 실험 기본값

- UTC 일봉 마감마다 그날 이미 알려진 같은 도형 버전의 경계를 사용한다. 수평선은 폭 0인 존이다. 추세선은 두 좌표가 확보된 뒤 기존 직선 보간·연장 함수를 적용한다. 이전 종가는 전일 경계, 오늘 종가는 당일 경계와 비교한다.
- 전일 종가가 전일 상단 이하이고 오늘 종가가 당일 상단을 초과하면 상향 돌파다. 이후 봉에서 저가·고가가 존과 교차하고 종가가 상단 이상이면 롱 후보가 한 번 나온다. 돌파 봉에서는 후속 시험을 인정하지 않는다. 존 내부 마감은 주의, 하단 미만 마감은 실패다. 상단과 같은 종가는 지지 확인에 포함한다. 캔들 모양과 거래량은 상세 근거로만 사용한다.
- 하단 아래 마감한 뒤 별도 봉에서 상단 이상으로 회복하면 하향 이탈 실패 관찰이다. 회복 사실과 다음 봉 이후의 지지 확인을 분리한다. 하단을 아래에서 시험한 뒤 상단을 회복하지 못하고 하단·전일 종가보다 낮게 마감하는 숏 경로는 기존 상승 대응 규칙을 쓴다. 접촉 후 존 안에서 마감해도 거부가 확인될 때까지 기다린다.
- 기존 수평선·존 숏 후보 및 롱 종료 검토에는 상승 실험과 같은 사건 ID를 사용한다. 우상향선 종가 이탈에도 기존 롱 종료 ID를 쓴다. 추세선의 아래쪽 재시험은 기존 하단 접촉·재하락 조건을 당일 선 가격에 적용한다. 두 실험을 함께 열면 공유 판단은 한 번만 강조하고, 서로 다른 도형의 판단은 유지한다.
- 종가 돌파와 몸통이 경계를 넘지 않은 꼬리 스윕을 구분한다. 양쪽 꼬리가 모두 넘은 봉의 스윕 방향은 확정하지 않는다. 기존 EMA9·20·50 배열과 가격 구조를 그대로 사용하며 급등은 선행 조건에 들어가지 않는다.
- **재시험 대기와 후보 표시에는 각각 8개 후속 봉**을 쓴다. 급락 실험과 동일한 비교 기간을 택했다. 돌파일·이탈일을 d로 두면 d+8까지 포함하고 d+9에 만료한다. 하향 이탈 뒤 회복하면 회복일을 새 대기 창의 시작으로 잡는다. 후보를 발행하면 표시 기간은 발행일부터 다시 센다. 기존 상승 패널에서 추적하던 숏의 기한은 종전 규칙을 따른다.
- 유효한 롱은 종가가 하단 또는 그날의 선 아래로 내려가면 무효다. 수동 도형 삭제·시간 범위 종료와 좌표 교체는 가격 무효·기간 만료와 별도의 사건이다. 원래 발행일·사건 ID·단계별 경계는 보존한다. 이 값들은 차트 비교용이며 최적화하지 않았다.

## 실행한 검사와 한계

- 고정 1,762봉과 합성 11개 경로 221봉을 하루씩 재생했다. 1,983개 접두 구간에서 당시까지의 전체 출력이 일치했다. 각 입력에 미래 4봉과 과거 좌표를 가진 새 도형 기록 1개를 추가해도 기존 날짜의 출력은 같았다. [경로별 발생 건수와 날짜](replay_result.json)
- 고정 구간에는 당시 도형 버전을 입증하는 이력이 없어 돌파 사건 0건이다. 합성에서는 59건의 사건에 고유 롱 후보 9건, 숏 후보 2건이 포함됐다. 중복 사건 ID와 같은 시도·유형의 후보 재발행은 각각 0건이다. 이 수치는 거래 건수와 수익률을 측정하지 않는다.
- PR #2 기준 소스를 별도 임시 디렉터리에서 실행했다. 고정 1,762봉, 합성 지지 재시험·추세선 입력에서 기존 상승·급락의 전체 일별 결과가 일치했다. 세 입력의 기존 일봉·주봉 대시보드와 마지막 날 상승·급락 API 응답도 일치했다. [기준 커밋과 비교하는 실행기](compare_legacy.py)
- 백엔드 463개, 급락 연구 99개, 프런트 180개 통과. 타입 검사와 프런트 빌드 통과. lint는 오류 0개와 기존 경고 3개, 백엔드는 테스트 라이브러리 사용 중단 예고 1개였다. 실제 Chromium에서 고정 1회·합성 24회 차트 날짜를 선택했다.
- 현재 개인 매매·도형 DB와 부속 파일, 지지 이력과 lock의 10개 경로를 검사 전에 기록하고 존재하는 세 파일은 Git 밖에 해시 확인 사본으로 보존했다. 검증 서버와 테스트는 임시 저장 경로만 사용했다. 종료 시 첫 해시 읽기에서 공유 위반이 발생했고, PowerShell 배열 처리 오류로 lock 변경 경보도 발생했다. 독립적으로 사본 세 개의 SHA-256을 확인하고, 실제 10개 경로 전후를 세 차례 다시 비교한 결과 변경은 0개였다. 사본에 남은 도형의 첫 관찰 시점은 고정 일봉 마지막 날 이후다. 이전 trades.db 사고의 사고 전 원본 복구·데이터 영향은 계속 미확인이다. [개인 파일 보호 및 과거 사고 기록](../ccx_rapid_drop/HANDOFF_V03.md)

## 다음 기기

저장소 루트에서 실행한다. 새 실험의 서버 플래그 `CCX_ENABLE_BREAKOUT_RETEST`와 일봉 패널 토글은 모두 기본 OFF다. 재현 서버는 프로세스 안에서만 실험을 켜고 외부 요청을 차단한다.

```powershell
git fetch origin
git switch feat/breakout-retest-signals
git pull --ff-only
npm.cmd --prefix frontend run build
& .\backend\.venv\Scripts\python.exe -B research/breakout_retest/validation.py --case zone_failure --port 18742 --frontend
```

브라우저에서 http://127.0.0.1:18742 를 열고 일봉의 **돌파·재시험 · 실험**을 켠 뒤 위 날짜를 클릭한다. 상세의 **도형·가격과 사건 순서**에서 버전, 당시 경계, 원래 확인일, 연결 ID를 볼 수 있다. 입력을 바꾸려면 검증 서버를 종료하고 `--case` 값을 바꿔 다시 실행한다. API 예시는 `GET /api/breakout-retest?date=2022-01-05`다.

```powershell
& .\backend\.venv\Scripts\python.exe -B research/breakout_retest/replay.py --workers 4 --output (Join-Path $env:TEMP 'ccx-breakout-replay.json')
& .\backend\.venv\Scripts\python.exe -B research/breakout_retest/compare_legacy.py
```
