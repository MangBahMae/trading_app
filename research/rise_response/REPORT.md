기준은 PR #1 병합 후 `main`의 `226b98972654c739469532e9e1d90e43f0ec8cad`이다. 실험을 켜고 차트에서 일봉을 선택하면 시장 상태, 기존 롱 종료 검토, 숏 관찰·후보를 각각 표시한다. 상세에는 후보 발행일, 기준 가격, 원래 관찰과 해제의 연결, 수동 도형 버전이 남는다. 날짜는 UTC 일봉의 시작일이며 판정은 그 봉이 마감된 뒤 확인할 수 있다.

## 실험에 사용한 정의

| 판단 | 적용값과 선택 이유 |
|---|---|
| 급등 시작 | 기존 캔들 판별기의 장대양봉 몸통 기준 `(C−O)/O ≥ 3.5%`. 기존 시세분출 계산의 3봉 12% 또는 4봉 16%는 창의 첫 시가와 마지막 종가를 쓴다. 기존 필터는 다음 약세 봉에서 직전 창을 조회한다. 이 실험의 시장 판정은 창 마지막 봉 마감에 이미 계산할 수 있다. 충족한 출처를 모두 상세에 남긴다. |
| 상승 구간의 끝 | 충격을 만든 창의 시작 시가를 유지 기준으로 삼는다. 같은 날 여러 창이면 그중 가장 낮은 시가를 쓰고, 구간 중 새 충격이 나오면 유지 기준을 높일 수 있다. 종가가 유지 기준 미만이면 일반으로 전환한다. 기존에 발행한 고점 관찰의 해제는 따로 추적한다. |
| 고점 횡보 | 급등 뒤 3개 마감봉을 사용한다. 3봉 모두 직전 구간 고점의 2% 이내 이상에서 마감하고, 공통 고저 범위가 세 봉 중 가장 짧은 고저 폭의 50% 이상이며, 최고가 전진이 직전 구간 고점 대비 1% 이하여야 한다. 한 봉만 겹치거나 가격이 이미 크게 내려간 경우를 걸러낸다. |
| 구분되는 눌림과 재상승 | 첫 고점보다 낮은 고가와 그 고점에서 2% 이상 내려온 종가로 눌림을 확인한다. 이후 별도 봉이 전일 고가·종가를 모두 높이고, 고가가 눌림폭의 절반 이상을 되찾아야 재시도다. 깊어지는 눌림 자체를 재시도로 세지 않는다. |
| 두 번째 고점 실패·해제 | 첫 고점 ±1% 이내는 유사 고점, 더 낮으면 낮은 고점이다. 두 번째 시도의 고가가 더 높아지면 기준 봉을 갱신한다. 이후 별도 봉이 그 봉의 저가 아래로 **종가** 마감할 때 처음 관찰을 발행한다. 첫 고점보다 1% 높은 가격을 **종가가 초과**하면 원래 관찰 ID를 연결해 해제한다. 서로 다른 상승 구간의 관찰은 각자 추적한다. |
| 우상향 수동선 | 기존 추세선 가격 보간·연장 계산을 쓴다. 같은 버전의 직전 종가가 선 이상이고 오늘 종가는 오늘 선 미만일 때 롱 종료를 검토한다. 시가·종가가 선 이상인 꼬리 이탈은 상세 관찰이다. |
| 지지 이탈·재시험 | 수평선은 폭 0인 존이다. 같은 버전에서 직전 종가 ≥ 하단, 오늘 종가 < 하단이면 이탈. 별도 봉의 직전 종가 < 하단, 시가 ≤ 하단 ≤ 고가이면 아래쪽 접촉이다. 접촉 당일이나 이후 종가가 하단과 전일 종가를 모두 밑돌면 첫 후보를 발행한다. 종가 ≥ 상단은 회복이다. 존 중간에 들어온 종가는 계속 관찰한다. 좌표가 바뀌면 구버전의 이탈을 신버전 재시험에 쓰지 않는다. |

횡보와 고점 재시도는 독립적으로 검사한다. 기존 횡보 표시의 EMA 배열·교차는 고점 가격대 겹침을 측정하지 않아 새 실험에서 가격 범위를 직접 사용했다. 3봉·50%·1%·2%와 재시도 확인선은 비교를 위한 기본값이다. 고정 일봉 결과로 최적화하지 않았다.

## 도형 이력과 재현

기존 JSONL v1에 있던 수평선·존의 관찰 시점과 버전을 유지한다. v1의 미지원 추세선 ID만으로 좌표를 복원할 수 없다. 새 v2 레코드에는 두 좌표를 기록하고, 최초 관찰일과 두 번째 좌표 날짜 중 늦은 날부터 적용한다. 최초 이탈에는 직전 마감부터 같은 버전이 필요하다. 외부에서 도형을 바꾼 정확한 시각은 앱이 관찰한 사이로만 한정할 수 있다. 구버전 전용 리더는 v2 기록을 읽을 수 없다.

다음 기기에서는 `git fetch origin`, `git switch feat/rise-response-experiment`, `git pull --ff-only` 후 저장소 루트에서 실행한다. 프로젝트 Python 가상환경과 프런트 의존성이 필요하다.

```powershell
Push-Location frontend
npm.cmd run build
Pop-Location
& .\backend\.venv\Scripts\python.exe -B research/rise_response/validation.py --case high_retry --port 18741 --frontend
```

브라우저에서 `http://127.0.0.1:18741`을 열고 일봉의 **상승·급등 대응 · 실험**을 켠 뒤 2022-01-07을 클릭한다. 고정 데이터는 같은 명령의 `--case fixed`, 롱 종료 사례는 `--case trendline`이다. 이 서버는 두 실험을 검증 프로세스 안에서만 켜며 거래·수동선 DB와 지지 이력은 임시 경로에 둔다. 앱 기본 설정은 서버와 차트 모두 OFF다. 실제 서버에서의 상승 실험 플래그는 `CCX_ENABLE_RISE_RESPONSE`다.

모든 재생을 다시 확인하려면 `python` 대신 위와 같은 프로젝트 venv로 `research/rise_response/replay.py --output <새 결과 경로>`를 실행한다. 실험 사건은 거래·체결·성과 측정에 사용하지 않았다. 이전 매매 DB 사고의 원본 복구·당시 데이터 영향은 기존 인계와 같이 미확인이다.
