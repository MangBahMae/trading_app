# 비트코인 트레이딩 어시스턴트 — 개발 킥오프 문서

이 문서는 Claude Code에게 프로젝트를 시작시키기 위한 지시서입니다.
전체 기획서(`docs/트레이딩앱_기획서_수정본.md`)는 21페이지 분량으로 매우 상세하지만,
지금 당장은 그 전체를 다 구현하려 하지 말고 **아래 "1단계 작업 범위"만** 정확히 구현해주세요.

---

## 0. 배경 (왜 이걸 만드는가)

- 매일 관심 종목을 하나씩 들어가서 차트를 확인하는 데 시간이 오래 걸리고 판단이 늦음
- 기준에 안 맞는 걸 알면서도 감정으로 합리화해서 진입하는 문제가 있음
- **핵심 방향**: 판단을 "그 순간의 감정"이 아니라 "미리 정해둔 기준"에 맡기는 구조를 만드는 것
- 지금 만드는 건 "관심종목 조건 스캐너"의 일부 — 여러 기술적 조건(스윙 고점/저점, 이동평균 배열, RSI, 캔들패턴 등)을 코드로 감지해서, 조건이 충족되면 알려주는 시스템
- **중요한 원칙**: 이 시스템은 최종 매매 판단을 대신 해주는 게 아니라, "지금 볼 가치가 있다"는 걸 알려주는 용도. 점수화나 우세 판단 없이, 조건이 떴는지 안 떴는지만 알려주는 "1차 단순 감지" 단계

## 1. 절대 원칙 — 반드시 지킬 것

1. **무지성으로 코드부터 짜지 말 것.** 아래 "1단계 작업 범위"에 정의된 것만 정확히 구현하고, 임의로 조건을 추가하거나 확장하지 말 것.
2. **모든 판정 로직은 아래 스펙에 명시된 파라미터(N값, %, 기간 등)를 그대로 사용할 것.** 표준적으로 다르게 쓰이는 값이 있어도, 이미 사용자가 결정한 값을 임의로 바꾸지 말 것. 바꾸고 싶은 이유가 있으면 반드시 먼저 물어볼 것.
3. **"확정(confirmed)" 방식만 사용.** 스윙 고점/저점은 오른쪽 N봉이 다 마감되어야 확정되는 지연이 있는 방식으로, "잠정" 상태는 만들지 않음. 이 지연을 우회하거나 없애려 하지 말 것.
4. **look-ahead bias(미래 데이터 누수) 절대 금지.** 특정 시점 T의 신호를 계산할 때는 T 시점까지 확정된 정보만 사용할 것.
5. **각 조건은 서로 완전히 독립적으로 계산.** 한 캔들이 여러 조건에 동시에 해당되면 각 신호가 모두 별도로 발생함 (조건끼리 서로 배타적이지 않음, 중첩 허용).

## 2. 검증 방법 — 반드시 이렇게 확인할 것

**코드를 짜고 숫자/날짜 목록만 출력하는 것으로 끝내지 말 것.** 반드시 아래 방식으로 시각적으로 검증 가능하게 만들어야 함:

1. 각 조건을 구현할 때마다, 실제 캔들차트(예: `mplfinance` 라이브러리 사용) 위에 해당 조건이 감지된 지점을 마커로 표시해서 이미지로 보여줄 것
   - 스윙 고점: 위쪽 삼각형 마커 (빨강)
   - 스윙 저점: 아래쪽 삼각형 마커 (파랑)
   - 기타 조건은 구현하면서 적절한 마커/색상을 정해서 제안
2. 사용자가 그 차트 이미지를 보고 "여기 이 지점은 맞다/아니다"를 직접 눈으로 판단할 것이므로, **차트는 한 화면에 너무 많은 캔들을 욱여넣지 말고(가독성 확보), 필요하면 구간을 나눠서 여러 장으로 보여줄 것**
3. 하나의 조건을 구현하고 시각적으로 확인받은 뒤에만 다음 조건으로 넘어갈 것. 여러 조건을 한꺼번에 구현하고 한꺼번에 검증받으려 하지 말 것.

## 3. 데이터

- 데이터는 `data/` 폴더 안에 바이낸스 BTCUSDT 일봉 CSV로 준비되어 있음 (data.binance.vision에서 받은 공식 데이터)
- 컬럼 형식은 바이낸스 klines 표준 형식 — 먼저 실제 파일을 열어서 컬럼 구성을 확인하고 시작할 것 (open_time, open, high, low, close, volume 등)
- 타임프레임은 **일봉만** 사용. 4시간봉/주봉/월봉 등은 지금 단계에서 다루지 않음

## 4. 1단계 작업 범위 (지금 구현할 것 — 이 순서대로 하나씩)

### 4-1. 스윙 하이/로우 판독

- 중심 캔들 `i`가 좌우 `N=2`개 캔들의 고가/저가보다 **엄격히(`>`, `<`)** 높거나 낮으면 스윙 하이/로우로 판정
- 동률(같은 값)은 스킵 — 오차 허용 로직 없음
- **확정 방식**: 스윙 포인트는 우측 N봉이 모두 마감되어야 "확정"됨. 즉 i번째 캔들이 스윙 하이인지 여부는 i+N 시점에야 알 수 있음. 이 지연을 데이터프레임에 명시적으로 표현할 것 (예: `confirmed_at` 컬럼)
- 판정은 종가가 아니라 **고가/저가** 기준

### 4-2. 다우이론 (HH / LH / HL / LL)

- 4-1에서 찾은 확정된 스윙 포인트들을 시간순으로 나열
- 새로운 스윙 하이가 확정될 때마다, **직전 스윙 하이 1개와만** 비교:
  - 더 높으면 HH (Higher High)
  - 더 낮으면 LH (Lower High)
- 새로운 스윙 로우가 확정될 때마다, **직전 스윙 로우 1개와만** 비교:
  - 더 높으면 HL (Higher Low)
  - 더 낮으면 LL (Lower Low)
- HH/LH/HL/LL은 각각 독립적인 개별 이벤트로 기록. "지금 상승추세다/하락추세다" 같은 종합 라벨은 만들지 말 것 (이건 나중 단계)

### 4-3. 이동평균 배열 판정

- MA9, MA20, MA50, MA200 (단순이동평균, SMA) 계산
- **정배열(기본)**: MA9 > MA20 > MA50 이면 정배열. 여기에 MA200까지 순서가 맞으면(MA9>MA20>MA50>MA200) "강한 정배열"로 별도 표시
- **역배열(기본)**: MA9 < MA20 < MA50 이면 역배열. MA200까지 맞으면 "강한 역배열"
- **수렴**: MA50이 MA20 또는 MA200과 가격 대비 폭 1.5% 이내로 좁혀지면 성립. 단, **정배열/역배열 조건이 이미 성립하면 수렴보다 정배열/역배열이 우선** (즉 순서 조건이 맞으면 폭이 좁아도 수렴이 아니라 정배열/역배열로 판정)
- **혼조**: 위 세 가지 중 어느 것도 아닌 경우

### 4-4. 지지/저항 터치 (MA50, MA200만 대상)

- 저가/고가(꼬리 포함)로 "터치 여부" 판단, 종가로 "성공/실패" 판단
- 이평선을 뚫고 종가가 반대편에서 마감 → 뚫린 정도와 무관하게 무조건 실패로 판정
- 애매하게 걸쳐서 마감(뚫지도 지키지도 않음) → 즉시 판정하지 않고 다음 캔들에서 재판단
- 터치 자체가 없으면 신호 없음
- 반복 터치도 매번 독립된 별개 신호로 기록

### 4-5. 도지캔들

- 판정식: `|종가 - 시가| / (고가 - 저가) ≤ 10%`

### 4-6. 매물소진 패턴 (신규 커스텀 조건)

- 판정식은 도지와 다름: `|종가 - 시가| / 시가 × 100` (등락률 방식)
- 조건: 직전 캔들의 이 값이 3.5% 이상 + 이번 캔들의 이 값이 직전 캔들의 절반 이하 + 이번 캔들 거래량이 직전 캔들 거래량의 50% 이상 (상한 없음)
- 방향(양봉/음봉) 무관 — 직전 캔들이 음봉이면 매수 신호, 양봉이면 매도 신호로 대칭 적용 (이번 캔들 방향은 무관)
- 도지 조건과는 완전히 독립적으로 계산 (중첩 허용)

### 4-7. 거래량 급증

- 기준 평균: 최근 20봉 중 **주말(토·일) 캔들은 제외**하고 평일 캔들만 모아서 평균 계산
- 판정: 당일 거래량이 이 평균의 1.3배 이상이면 급증

### 4-8. RSI

- Wilder 방식 14기간 RSI 계산
- 다이버전스 판정 기준선: 70/30 사용, 최근 스윙 1쌍만 비교
  - 정상 강세 다이버전스: 가격 저점이 LL인데 RSI 저점이 HL
  - 정상 약세 다이버전스: 가격 고점이 HH인데 RSI 고점이 LH
  - 은닉 강세 다이버전스: 가격 저점이 HL인데 RSI 저점이 LL
  - 은닉 약세 다이버전스: 가격 고점이 LH인데 RSI 고점이 HH
  - (RSI 값은 별도 스윙 탐색 없이, 4-1에서 찾은 가격 스윙 확정 시점의 RSI 값을 그대로 사용)
- 별도 과매수/과매도 신호 (다이버전스와 별개): RSI ≤ 25 → 매수 신호 / RSI ≥ 80 → 매도 신호. 단순 임계값이며, 그 구간에 머무는 동안 매 캔들 반복 발생 (크로스백 아님)

## 5. 지금은 하지 않을 것 (범위 제외)

- 쌍고점/쌍바텀, 라운딩탑/바텀, 수동 지지선/저항선 등록, 발산/횡보 국면 판정(1-H) — 이런 것들은 이번 1단계에 포함하지 않음. 위 4-1~4-8이 다 구현되고 검증된 뒤에 이어서 요청할 예정
- 청산/익절/손절 로직 — 지금은 "진입 신호가 원하는 시점에 정확히 발생하는지"만 확인하는 단계이며, 수익률 계산이나 실제 매매 시뮬레이션은 하지 않음
- 4시간봉/주봉/월봉 등 다른 타임프레임 — 일봉만 우선 완성

## 6. 진행 방식 요청

1. 먼저 `data/` 폴더의 CSV를 열어서 구조를 확인하고 알려줄 것
2. 4-1(스윙 하이/로우)부터 구현하고, 차트로 시각화해서 보여줄 것
3. 사용자가 확인/승인하면 4-2로, 순서대로 하나씩 진행
4. 각 단계에서 애매하거나 스펙에 없는 예외 상황이 발생하면 임의로 판단하지 말고 반드시 먼저 물어볼 것
